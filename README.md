# 後端基本功

給新進後端工程師的入門教材，共 59 篇。每篇講一個新人在前幾個月一定會遇到的主題：兩個請求同時改同一筆資料會發生什麼、為什麼加了索引還是慢、重試為什麼會把下游打垮、訊息佇列為什麼會重送。每篇從一個具體的出事情境開始，用時間軸和圖講清楚機制，最後告訴你哪些是一定要會的基本功、哪些先知道就好。

網站上另外有三頁：

## 每篇怎麼讀

每篇的段落順序都一樣：

1. **核心問題與理念**：它要解決什麼問題、核心的想法（一句白話），以及「想通的那一步」：直覺的做法卡在哪裡、哪一個轉念讓問題迎刃而解。
2. **閱讀前推薦具備知識**：讀這篇要先會什麼、要會到什麼程度、不熟的話先看哪裡，附一題自我檢查。
3. **為什麼要在意**：一個具體的出事情境，有時間軸，看得到兩個請求在 T1、T2 各做了什麼、數值怎麼變。
4. **全貌**：一張小圖，標出這個主題發生在系統的哪裡。
5. **生活比喻**和**它是怎麼運作的**：先有直覺，再一步步看機制。
6. **動手看看**：在本機用 Docker 跑得起來的實驗，範例都實際跑過。
7. **常見地雷**：錯誤寫法和正確寫法並排。
8. **重點整理**、**新人必知清單**、**Code Review 時可以問的問題**、**情境演練**。

網站上的時間軸表格可以「逐步看」：按一下就一列一列往下亮，看清楚事情發生的先後。每篇也有一張可以播放、拖時間軸的主圖，把最關鍵的那段機制畫出來。

範例統一使用 PostgreSQL、Redis 和 Python；MySQL 行為不同的地方，文中會另外註明。第十二章「設計與分層」的範例和練習題用 Java 21 和 JUnit 5。

## 在本機預覽

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/mkdocs serve
```

Windows 上把 `.venv/bin/` 換成 `.venv\Scripts\`。打開 <http://127.0.0.1:8000> 就能看到網站，改了 `docs/` 裡的檔案會自動重新整理。

## 部署到 GitHub Pages

- 每次 push 到 `main`，`.github/workflows/pages.yml` 會用 `mkdocs build --strict` 建置，並把結果發布到 GitHub Pages。連結壞掉時建置會失敗，不會發布出壞掉的網站。
- push 到其他分支或開 PR 時只建置，確認會過，不會發布。
- Pages 的來源設在 repo 的 **Settings → Pages → Source: GitHub Actions**。

## 改文章時

- 文章在 `docs/`，一篇一個檔案。新增文章要同時加進 `mkdocs.yml` 的 `nav`。
- 文章之間用相對連結，例如 `[死鎖](02-死鎖.md)`。檔名有空白時寫成 `%20`，例如 `[N+1 查詢](09-N+1%20查詢.md)`。
- 時間軸表格的第一欄標題寫「時間」或「步驟」，網站就會自動加上逐步播放的按鈕。
- 摺疊的答案寫成 `<details markdown="1"><summary>看答案</summary> … </details>`。`markdown="1"` 不能拿掉，少了它，答案裡的 Markdown 不會被轉換。
- 圖用 Mermaid。節點文字含中文、括號、冒號時用雙引號包起來。
- 網站樣式在 `docs/assets/extra.css`，逐步播放和手機版表格在 `docs/assets/extra.js`。
