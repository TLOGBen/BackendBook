# 難度地圖

這一頁記錄每篇文章「從上讀到下」的理解難度。審閱代理用剛入行工程師的眼光讀每一篇，每個段落打 1 到 5 分：1 是一讀就懂，3 是要回頭重讀或查一個詞，5 是讀不下去。接著把卡住的地方補平，再用同樣的眼光重讀一次打分。

曲線裡每一格是一個段落，由上到下排：▁ 1 分、▂ 2 分、▄ 3 分、▆ 4 分、█ 5 分。

## 整體

| 指標 | 改前 | 改後 |
|---|---:|---:|
| 4 分以上的段落 | 106 | 0 |
| 每篇最難段落的平均分數 | 3.9 | 2.9 |
| 相鄰段落難度一口氣跳 3 分以上 | 0 | 0 |
| 相鄰段落難度一口氣跳 2 分以上 | 28 | 29 |

跳 2 分的落差沒有變少。改後的落差幾乎都在同一個地方：「生活比喻」（1 分）接到「它是怎麼運作的」（3 分）。比喻本來就好讀，運作原理是每篇的主體，讀到這一節放慢速度是正常的。

改前最常見的卡關原因是開頭的「先講結論」用了還沒解釋的術語，以及情境寫得太空泛。改後結論移到文末的「重點整理」，情境改成看得到程式碼和時間軸的具體案例。分數是審閱代理的判斷，不是實測，拿來找出哪幾段最需要多花時間讀就好。
